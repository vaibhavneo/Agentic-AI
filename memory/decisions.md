# decisions.md — Architecture Decisions
<!-- Irreversible/settled choices ONLY. One line of rationale each. No plans, no state. -->

- **D1 — Memory root**: `~/Desktop/Agentic AI/memory/` (project-relative; root `/memory/` is not writable on macOS).
- **D2 — Retrieval engine**: TF-IDF (pure Python, reuse proven in-repo pattern) — no vector DB, no embeddings API. Upgrade path documented, not built.
- **D3 — Ingest source order**: wiki/books/ (36 curated) first, raw/library/ (456 books) later — signal density over volume for MVP.
- **D4 — Chunk store**: single JSON file `memory/index/chunks.json` — simplest correct thing; SQLite only if size/concurrency demands it.
- **D5 — knowledge_cache.md format**: append-only mental models, each = `## Name` + Principle + When-to-use + Sources. Dedup by name.
- **D6 — LLM for distillation**: reuse existing key resolution (DeepSeek from .env, Anthropic fallback) — same as vedic_astro/stock_agent convention.
- **D7 — Loop control**: file-driven — loop.py reads Stability Criteria from state.md; no in-memory loop state. Max plan depth 3, atomic steps.
- **D8 — No chat-history memory**: all progress persists in memory/*.md; any session can resume from files alone.
- **D9 — Concept store**: `memory/concepts.json` is the source of truth; `knowledge_cache.md` is a rendered view regenerated by `concept_store.render_markdown()` — never hand-edited (structured data + relationships need machine-readable form).
- **D10 — Critic is deterministic**: confidence = 0.5·retrieval_support + 0.5·source_corroboration, computed from TF-IDF evidence — no LLM self-grading (an LLM judging its own distillations reintroduces the hallucination loop the critic exists to break).
- **D11 — Honest flags over gamed scores**: concepts whose provenance the index cannot confirm stay flagged (e.g. workspace-experience claims) — the fix is ingesting more sources, never editing the verdict.
- **D12 — Skill Runtime**: skills execute ONLY via manifest+contracts through brain/runtime/ dispatcher (9-step lifecycle, typed failures, memory-write verification against manifest allowlists). Reasoning enters via context adapters (`task_executor`/`agent_adapter`) — the runtime never embeds a model.
- **D13 — Repository as sole source of truth (2026-07-05)**: all architectural knowledge lives in repo docs (charter/handbook/playbook/LESSONS/adapters); conversation history is disposable. Per-skill README.md files are GENERATED from manifest.json — edits go to manifest+skill.md. manifest.json (not YAML) remains the one machine format.
- **D14 — AIOS Core extraction (2026-07-05)**: the runtime is reusable infrastructure and now lives in `aios_core/` (engine `aios_core/runtime/` + six stable SDK APIs `aios_core/sdk/`: skill, workflow, agent, memory, retrieval, mission). Applications depend ONLY on `from aios_core import ...` (P10, req #3). The skill LIBRARY stays in `brain/skills/` (content the core loads; AIOS_SKILLS_DIR-configurable). `brain/runtime/*` kept as re-export shims (module identity preserved) for backward compat; removal would be a v2.0.0 breaking change. Duplicated thread-runner glue collapsed into `workflow.BackgroundRun`.
- **D15 — Domain Packs (2026-07-05)**: independent knowledge domains ship as self-contained `packs/<id>/` (pack.json + skills/drivers/workflows/corpora/mission_templates/evaluation/memory/tests) loaded by `packs/loader.py::PackManager` through documented core interfaces ONLY (composite Registry via `dispatch(registry=)`, `retrieval.register_corpus`, Mission SDK) — ZERO AIOS Core modification, enforced by a test asserting the core registry is unchanged after load. Descriptor is pack.json not pack.yaml (D13 consistency). Reference pack: `packs/ai_engineering/`. Four packs specced (AI-eng impl; PM/finance/astrology wrap existing code). See DOMAIN_PACKS.md.
- **D16 — Mission Control (2026-07-06)**: `/` (port 8003) now serves Mission Control (10-panel dashboard: missions/priorities/learning/knowledge/project/insights/health/memory/decisions/timeline), superseding the P0 shell as the default landing page (`/app` unchanged — mission workspace; legacy tutor moved to `/legacy`). Implemented as vanilla JS (no build pipeline exists anywhere in this repo yet); the React component hierarchy + state architecture are documented as the migration target in MISSION_CONTROL.md so a future port is mechanical, not a redesign (LESSONS.md's "React remains the documented target" made concrete). Backend: `learn_agent/mission_control_service.py` aggregates ONLY through the aios_core SDK (verified by a source-level test — no second_brain/corpus_manager imports, no reimplemented skills). One new deliberate logic: a 3-rule deterministic proto-coach for "today's priorities", explicitly labeled as superseded by the real Coach Service (M-P1a).
- **D17 — Skill Authoring SDK (2026-07-06)**: skill engineering is a documented, validated, model-agnostic process: canonical full-profile layout (`templates/skill/`, 11 files incl. per-skill contracts/examples/tests/CHANGELOG), 9-stage deterministic validator + 8-category quality score in `aios_core/skill_sdk/` (homed per D14 — NOT the requested `/skill_runtime/validators/` path). `purpose` is the 12th REQUIRED manifest key (runtime.md fixed — closes Q1g). New skills: full profile + quality ≥85; legacy library passes reduced "core" profile, migrates opportunistically (R16). Proven by Part-10 benchmark: concept_map recreated from docs alone → 4/4 behavioral set-parity, 23/23 valid, exposing real ordering under-specification (G1) in the original contract.
- **D18 — Skill Capability Descriptor (2026-07-06)**: OPTIONAL per-skill `capability.json` — advisory metadata ABOVE the manifest (routing hints preferred_models/reasoning_level/estimated_tokens, semantic I/O roles, quality_requirements). Deliberately NOT part of manifest.json: the dispatcher never reads it (test-enforced), so model names live here as config DATA without violating P8 (manifest stays model-agnostic; MODEL_EXECUTION_GUIDE precedent). Verified not asserted (P6): `deterministic` cross-checked vs skill.md, `min_test_coverage` a REAL stdlib-trace line measurement (recursive_planner 100%, 62/62). Router (`capability.route`) is advisory + data-driven (hardcodes no model). Optional validator stage V10. Caught recursive_planner's descriptor claiming determinism its skill.md didn't document → fixed by documenting the truthful mechanical/executor split (P7, not gamed).
- **D19 — Retire distill.py's LLM path (2026-07-10, resolves H5/Q1i)**: `second_brain/distill.py` (the cycle-1 standalone DeepSeek→Anthropic CLI distiller) is DELETED, not exercised. Evidence: zero importers/callers (only its own `__main__`); no workflow or skill depends on it (WORKFLOWS.md chains the `concept_distillation` agent-type skill, which is `runtime:agent`, adapter-gated, and depends on `retrieve_context` — never on distill.py); the loop's `"distill"` stability signal is `n_models>=3`, a concept count, not an execution of the file. It also VIOLATED current contracts: direct `Retriever` use outside the gateway (P9) and appending to `knowledge_cache.md`, the rendered view D9 forbids hand-editing (concepts.json is source of truth). The capability it provided is already supported model-agnostically by `concept_distillation` (RETRIEVE→COMPRESS→DEDUP→UPSERT, reasoning via `agent_adapter`; a real model wires in exactly as the M-P2a teacher will). Amends PROJECT_CHARTER.md §5 (drops `distill` from the second_brain listing). Regression: `test_library_skills.py` proves the supported path works (concept_distillation NOT_EXECUTABLE without an adapter; schema-valid concept with a stub adapter; OUTPUT_INVALID on a bad one). Do-not-preserve-dead-code (charter §4 philosophy) over exercising vendor-coupled, contract-violating code no caller needs.
